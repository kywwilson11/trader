### validation

- n_eff floor of 10 in deflated_sharpe_ratio:102 and dsr_from_trade_returns:143 [5/5 reviewers; MODEL-FACING] — a measured effective breadth below 10 is silently raised to 10, loosening the gate exactly where the crowding correction should bite (verified: 30 trades / n_eff=4 -> DSR 0.784 PASS vs honest ~0.42-0.50 FAIL; reachable from backtest.py:326-328 clustered_effective_n and hypersearch_v2.py:1213 on the 6-coin book). Sketch: (a) fail-closed — measured n_eff<10 returns the all-zero dict like n_obs<10 (matches repo posture); (b) drop the floor to a numerical guard (ne>1; sqrt(ne-1) is the only real constraint) and use the honest value; (c) keep + document. Raw non-positive n_eff (0, -5 — sample_weights.effective_n can return 0.0 on all-NaN spans) is currently promoted to 10 too and should fall back to IID like NaN does. The shipping 'n_eff_requested' key makes occurrence measurable on real Jetson retrains BEFORE deciding.
- n_trials sourcing for the two promotion gates [5/5; MODEL-FACING, cross-file] — hypersearch deflates by cumulative COMPLETE-only trials of the resumed study (pruned excluded: MedianPruner kills roughly half of post-startup trials, each still a selection event -> systematic under-deflation), while backtest --gate uses this-run's --trials (argparse default 100; run_pipeline passes max(trials,10)); measured 21-37% bar difference, enough to straddle DSR_MIN. Sketch: hypersearch records its pool (COMPLETE+PRUNED) into config['holdout']['n_trials'] (free once the echo ships), backtest reads it with --trials as fallback/override; decide the pruned-trial convention explicitly; stale-study N inflation after objective changes (gotcha #2) argues for fingerprinting trials on resume.
- serial_correlation_factor sharpe_scale clamp [5/5 observed, 3/5 say defer; STATISTICAL-DEFINITION] — n_eff is clamped to <=n but sharpe_scale reaches 1.90 (phi=-0.6) / 1000 (at the f floor); Lo's correction is genuinely two-sided, so min(1.0, 1/sqrt(f)) is a house-conservatism choice, not a bugfix. Docs shipped now state it is unclamped; decide clamp vs raw-value-with-renamed-key before any caller is wired.
- build_oos_blocks scale bias [R4-P1 + R5; MODEL-FACING] — block-mean Sharpe scales as sqrt(trades-per-block), so CSCV ranks partly by trade count (measured: identical-true-skill populations, PBO 0.69 uniform vs 0.17 heterogeneous — false comfort in the fail-open direction, and trade_threshold/forward_bars are searched hyperparameters). Sketch: bin on a shared CALENDAR grid (pass exit timestamps + common span; inactive blocks contribute 0.0 — the Bailey et al. construction), or minimally standardize each row by its own per-trade std and switch perf_fn to plain mean (partial fix). Decide BEFORE wiring cscv_audit on the Jetson.
- PBO tie/degenerate-score semantics [R3 + R5; STATISTICAL-DEFINITION] — strict '<' ranking makes all-tied populations score PBO 1.0 ('maximally overfit') where the contract wants ~0.5/None, and _sharpe_cols scores a subset-constant positive row 0.0 (a genuinely best constant-return config loses argmax to noise). Sketch: mid-rank omega (beaten + 0.5*ties) and/or sign-aware scoring of zero-variance subsets. The shipped constant-ROW filter covers the realistic all-zero case; these remainders change diagnostic definitions.
- deflated_sharpe_ratio inconsistent-moment handling [R1 vs R2 conflict; latent public API] — when caller-supplied skew/kurt violate kurt >= 1+skew^2 (e.g. scipy Fisher excess kurtosis passed as-is) the 1e-12 denominator floor snaps DSR to exactly 1.0/0.0. Internal path provably safe (sample moments satisfy the bound). Options: clamp kurt to the Pearson bound (R1) vs fail closed to 0.0 when the variance term <= 0 (R2). Docstring warning ships now.
- skew/kurt absolute +1e-18 epsilons [R3, self-classified policy-semantics] — below ~1e-5 return scale the kurtosis collapses toward 0 and DSR drifts UP (fail-open), contradicting the docstring's unit-cancellation promise; portfolio_backtest's units are caller-defined. Sketch: drop the epsilons (m2>0 already guaranteed by the std guard); byte-identity is provable for percent-scale but not fraction-scale inputs, hence deferred. The shipped |SR|>1e3 guard catches the saturating extreme.
- Cross-file report-only items (do NOT edit from this pipeline): hypersearch_v2.py:1602 warns at PBO>0.25 where the null level is ~0.5 (fires on ~81-88% of skill-less searches; cscv_audit already uses 0.5) and prints nothing when <8 trials recorded fold_sharpes ('not measured' indistinguishable from 'clean'); backtest.py:508 gates n_trades on the raw count while DSR uses the finite-filtered count (NaN-degraded replays invisible) and its --trials accepts 0/negatives; scripts/cscv_audit.py should mirror the MAX_CSCV_SPLITS cap in ap.error and say 'sorted by exit time' in its recipe; backtest/hypersearch should echo the new dsr keys (n_trials, n_eff_requested, skew, kurt, expected_max_sr) into backtest_*_report.json / config['holdout'].
